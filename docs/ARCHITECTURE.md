# Steplight architecture

Steplight is a **record once, publish everywhere** platform for software training and digital adoption, inspired by ClickLearn (see `research/`). An author clicks through a business process in a web application while Steplight records it. From that single recording, Steplight produces:

- **Documents:** Word, PDF, PowerPoint and an HTML guide.
- **Interactive videos:** Show Me (narrated demo), Try Me (guided practice) and Test Me (scored assessment).
- **SCORM 1.2 packages** for an LMS.
- **A WebM video.**
- **Assist:** live in-app guidance that overlays the real application.
- **A branded learning portal** with search and AI help.
- **Translations** in 7 languages.
- **Replay**, which re-runs the recording against an updated application to refresh every screenshot, and doubles as **automated process testing**.

## Tech stack
- Node 22, TypeScript (ESM), run with `tsx` (no build step for server code).
- Express API server and file-based store (`data/`).
- Playwright (Chromium) for scripted recording, replay, PDF and video rendering.
- Browser libraries bundled with esbuild into `dist/lib/*.js`, each an IIFE that defines one global (`scripts/build-lib.mjs`).
- The Studio UI is React 18 + Vite, built into `dist/studio`.
- Output libraries: `docx`, `pptxgenjs`, `jszip`, `pngjs`.
- `@anthropic-ai/sdk` is optional. Without credentials, AI features run in offline mode.

## Data model (see `src/core/model.ts`, the source of truth)
- A **Project** has languages (the first is the source language), branding and an ordered `processIds`.
- A **Process** has `steps[]` and `localizations[lang]`.
- Each **Step** holds:
  - `action`: click, type, select, check, press, navigate or note.
  - `target`: selectors (most robust first) plus `tag`, `role`, `name`, `label` and `bbox` (viewport CSS px, matching the screenshot).
  - `value` / `optionValue`.
  - `title`: the auto instruction, editable. `titleEdited` stops it from being regenerated.
  - `description`, `screenshot` (a file name in the project media folder, PNG at viewport size, taken **before** the action) and `viewport`.
  - `draft`: set on a step drafted from an imported written guide until it is recorded: `source` (the guide's words), `flag` (what the author should check, cleared by "Mark as checked") and `added` (not in the guide). Its `target` is built from the element the guide names (`src/core/draft.ts`: role/label/text selectors, no `bbox` until a highlight is drawn), so instructions generate and translate as for recorded steps. The process records `importedFrom`.
- **Localization:** `localizations[lang].steps[stepId]` can override `title` and `description`, and can carry a localized `screenshot`, `bbox`, `name`, `label` and `value` captured by a **localized replay**. When no title is stored, `resolveProcess(proc, lang)` regenerates the instruction from templates, using the localized UI name. Instructions therefore localize without machine translation.
- **ResolvedProcess** is what players and generators consume: localized text, masked sensitive values, 1-based `index`, and `screenshot` as a URL (web) or an absolute path (generators).

## Browser library contracts (globals defined by `dist/lib/*.js`)
Each bundle injects its own CSS: import a `.css` file as text and add a `<style>` element once.

### `capture.js` → `window.SteplightCapture` (source `src/capture/browser.ts`)
```ts
SteplightCapture.start(emit: (ev: CaptureEvent) => void | Promise<void>): void   // starts listening (capture phase)
SteplightCapture.stop(): void
SteplightCapture.describe(el: Element): Target                                   // selectors + role/name/label/bbox
SteplightCapture.resolve(target: Target): { element: Element; index: number; selector: Selector } | null
```
- `click` events fire on **pointerdown** (so the screenshot shows the state before the click).
- `type` fires on `change`/blur. Its value is the final value of the field; password fields are marked sensitive.
- `select` fires on change. Its value is the selected option's **label** and `optionValue` is its value.
- `check` fires on change, with value `"true"` or `"false"`.
- `press` fires for Enter/Escape in a field. Tab is not recorded, because it would add a step after every field.
- Clicking into a text field, select or checkbox is not recorded as a step; the field's own type/select/check event is.
- A field that has been typed into but not yet blurred is flushed before the next click, so the steps stay in order.
- Element identity uses: `data-testid`/`data-test`/`data-qa`, `data-clid`, a stable `id` (not auto-generated looking), ARIA role + accessible name, label, placeholder, text and a CSS path.
- Selector value formats:
  - `role` → `"button|Save"` (role, a pipe, then the accessible name)
  - `label` → the label text
  - `text` → the visible text
  - `css` → a CSS selector
- `resolve` tries the selectors in order and returns the first visible, unique match. `index > 0` means the match was **healed**.

### `assist.js` → `window.SteplightAssist` (source `src/assist/browser.ts`)
```ts
SteplightAssist.start(process: ResolvedProcess, opts?: { ui?: Record<string,string>; startAt?: number; onEvent?: (type: "start"|"step"|"complete"|"exit", data?: unknown) => void }): void
SteplightAssist.stop(): void
```
- Highlights each live element (found with the same resolution logic as capture: import from `src/capture/resolve.ts`), shows a tooltip ("Step 2 of 7"), and advances when the user performs the action.
- Progress is kept in `sessionStorage` so it survives reloads.
- **Auto-start:** if the page URL contains `sl_assist=<url-encoded URL of /api/processes/:id/resolved?lang=xx>` (in the query or the hash), or the script tag has a `data-process-url` attribute, it fetches the process and starts.

### `player.js` → `window.SteplightPlayer` (source `src/players/browser.ts`)
```ts
SteplightPlayer.mount(el: HTMLElement, cfg: {
  process: ResolvedProcess; mode: "show" | "try" | "test"; ui?: Record<string,string>;
  autoplay?: boolean; voice?: boolean;      // show: speechSynthesis narration in process.lang

  scorm?: boolean;                          // report completion/score to an LMS SCORM 1.2 API (window.API in parent frames)

}): { destroy(): void }
```

### `portal.js` → `window.SteplightPortal` (source `src/portal/client.ts`)
Portal search and the AI chat widget.

## Importing a written guide (`src/server/guide-import.ts`)
1. **Read** (`docx.ts`): `word/document.xml` with its styles, numbering and relationships, into blocks in reading order: headings, paragraphs, numbered/bulleted items and table cells as text with `**bold**` runs, and the pictures between them.
2. **Pictures:** PNGs are kept as they are; JPEG, GIF, BMP, WebP and SVG are converted to PNG by Chromium (EMF, WMF and TIFF are skipped). Up to 20 are downscaled (1568 px long side) for Claude.
3. **Plan** (`guide-plan.ts`): with Claude configured, one structured-output request (`output_config.format` JSON schema, streamed) gets the guide as numbered lines plus its screenshots and returns the steps: action, element kind and name, value, learner choice, the guide's words, the screenshot that shows the step, a flag and whether the step was added. Without Claude (or when the request fails, with a warning) rules read the common phrasings: Steplight's own instruction templates, "Enter X in the Y field", "Set X to Yes", menu paths "A > B > C" (one click per entry). Lines no rule reads become flagged notes.
4. **Draft:** a new process with `draft` steps (see the data model), the guide's screenshots as placeholder screenshots, the start URL given at import (the test environment) and `importedFrom`. The Studio shows the draft banner, flags steps to check and lets the author fix the element, convert notes and draw highlights.

## Recording from a guide (extension "Record from the guide")
The author records a drafted process in their own browser, signed in to the application:
- The popup starts a build session (`POST /recordings {build: true}`), opening the process's start page first if the tab shows another site. The content script runs Assist (`AssistSession` with `persist: false`, no Back, a "That was it" button) over the plan: each draft step is highlighted, found by its selectors and then by a looser name search (`resolveByName`: "New" finds "+ New").
- Every captured action is sent with `build: {stepId, onTarget}`: the draft step shown and whether the action was on its highlighted element. `applyBuildCapture` (src/server/recording.ts) makes it that step (on target, or `draftMatches`: the guide's name and a fitting action) keeping the draft's id, explanation and learner choice, or inserts it as an extra step before the draft. The usual noise rules apply (typing again keeps the last value; a calendar click before the date is one step). The page is told where it went, so the card moves on or offers "That was it".
- A note gets a screenshot when the author moves on from it. The pill and the card are hidden, and a frame drawn without them, before each screenshot; screenshots are booked within `captureVisibleTab`'s two-a-second limit.
- The session ends with the last step (or Exit / Stop). Skipped steps stay drafts.

## Replay contract (`src/replay/replay.ts`)
- `replayProcess(proc, {mode, lang, mediaDir, saveMedia, baseUrl})` launches Chromium (1280×800 unless a step's viewport says otherwise).
- It opens `startUrl`; a relative URL is resolved against `baseUrl`.
- **To switch the application's UI language** it adds a `lang=<code>` query parameter, inside the hash query for hash routes and in the search string otherwise, and sets the context `locale`.
- For each step it resolves the target with the same logic as `SteplightCapture.resolve`:
  1. Inject `dist/lib/capture.js`, or fall back to Playwright locators built from the selectors.
  2. Wait for the target to be visible (timeout ≈ 5 s).
  3. Take a **screenshot before acting**, record the bbox and the element's current name/label, then perform the action (`select` uses `optionValue` when present).
- Each result is `ok` (first selector), `healed` (fallback selector, or the name changed) or `failed`.
- **Update mode, same language as the source:** writes the new screenshot, bbox and `replayStatus` into `steps`. Element names are refreshed only when the step title wasn't hand-edited.
- **Update mode, another language:** writes into `localizations[lang].steps[stepId]` (`screenshot`, `bbox`, `name`, `label`, and `value` = the displayed option label for selects). The base steps are left untouched.
- **Test mode:** writes no media and only reports. `passed` is true when no step failed.

## Demo application (`demo-erp/`)
- "Northwind ERP" is a static, hash-routed SPA (no build step), modelled on a modern ERP such as Business Central.
- Pages:
  - role-centre dashboard
  - list and card pages for customers, sales orders, items and purchase invoices
  - an action ribbon and dialogs
- UI languages **en / da / de**, chosen by `lang` in the URL (search or hash query); the choice persists in localStorage.
- **Layout version 2** (`v=2`, the same way) changes the layout (buttons move, some ids change, labels stay the same) so Replay's healing and testing can be shown.
- Data is seeded into localStorage, and `?reset=1` resets it.
- `/lib/assist.js` is included, so guidance works without the extension.
